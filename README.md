# 飞书多维表数据看板 · 集成测试

从飞书多维表真实拉取渲染的看板页面，用于验证《多维表数据看板集成 SOP》中的各项能力。

- 入口：`index.html`
- `vm.json`：构建时产出的视图模型，页面优先拉它（带时间戳查询串，绕开 10 分钟 HTML 缓存）
- `data.json`：原始数据快照，供对照
- 已脱敏：不含 base token、表 ID、租户地址

## 数据从哪来（页面顶部「数据来源」会写明）

取数顺序为「先实时，后兜底」，三条分支都在页面状态条上标识：

| 场景 | 数据来源 | 行为 |
| --- | --- | --- |
| 本机跑着 `node server.js` | **中转实时** | 每次打开都是当前值；写回后刷新**不会**退回旧值 |
| 公网访客（无中转） | **快照文件** | 读同目录 `vm.json`，是上次构建的结果，只读 |
| 本地 file:// 直接打开 | **构建快照** | 用页面内联快照兜底，离线也能看 |

这一层设计解决的问题：**「改了数据、页面也更新了，刷新一下又退回旧值」**。
根因是公网页面原本只有「构建时快照」，写回改的是多维表本身，两者不联动。

## 验证要点（悬停即看，无需点击）

| 项 | 验证方式 |
| --- | --- |
| 字段解析 | 悬停任意单元格 → 对照「接口原始值 / 页面解析值」 |
| 数据来源 | 悬停状态条「数据来源」→ 说明当前用的是哪一层数据 |
| 数据新鲜度 | 悬停右上角新鲜度徽标 → 拉取时间、阈值、降级原因 |
| 数据契约 | 改 Base 字段名后重新构建 → 契约面板报警，缺失槽位显示 `—` |
| 失败降级 | 断网构建 → 保留上次快照并标记「降级快照」，不假报成功 |

## 写回（双向读写）

页面**不持有任何凭证**。只有本机运行写回中转服务时才开放编辑，否则自动只读。

```bash
node server.js          # 写回中转服务（仅绑 127.0.0.1，默认 :3210）
```

明细表的 **状态 / 进度 / 超期** 三列可双击编辑（Enter 提交，Esc 取消）。
写回路径：页面 → `POST /api/update` → 中转服务 → 飞书 `PATCH records/{id}`。
约束：只绑本机 / Origin 校验 / 字段白名单 / 边界校验 / 乐观锁（旧值比对，冲突返回 409）。
写回成功后服务端回读真实值并返回重算过的完整视图，前端整体重绘。
